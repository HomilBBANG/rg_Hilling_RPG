## 요청 프롬프트

당신은 **Godot 게임 클라이언트 프로그래머 겸 그래픽 프로토타이핑 담당자**다.

이 작업 폴더에 있는 `GDD.md`, `GRAPHICS_PROTOTYPE.md`를 먼저 읽고 이 문서들을 개발 기준으로 사용하라.

### 반드시 지킬 사항

1. **이번 목표는 완성 게임이 아니라 P0 시각 기술 검증**이다. 몬스터 대량 생산, 퀘스트 시스템, 경험치/인벤토리/던전 등 전체 기능을 구현하지 말라.
2. **고정 탑다운 카메라 + 3D 월드의 픽셀화 렌더링**이 화면상 어떻게 보이는지 직접 비교할 수 있는 **실행 가능한 Godot 프로젝트**를 우선 만든다.
3. 프로젝트는 **Godot 4.x 현재 설치된 안정 버전**을 확인하여 그 버전에 맞춰 작성하고, 버전 의존 API는 테스트하라. 설치 버전을 확인할 수 없다면 해당 사실을 밝히고 검증 가능한 문법으로 작성하라.
4. 화면에는 **3D 자연환경, 인식 가능한 사람 캐릭터, 현대식 캠핑카, 판타지 몬스터 1종, 낮/밤, F키 캠핑카 라이트, 개인 등불, 간단한 캠핑카 실내**가 있어야 한다. 회색 큐브 몇 개만 만든 상태를 최종 납품이라 하지 말라.
5. **픽셀 렌더 프리셋 2종과 원본 3D 대조 화면** 사이를 전환할 수 있게 하라. UI 텍스트는 픽셀화 때문에 흐려지지 않도록 분리한다.
6. 플레이어는 WASD로 걸으며 카메라는 추적하되 **카메라 회전은 구현하지 않는다**. 디버그 키는 `GRAPHICS_PROTOTYPE.md`를 따른다.
7. `GDD.md`의 **[확정]** 사항을 변경하지 않는다. **[미정]**인 사항은 물어보는 대신 작은 개발용 가정으로 처리하고 `notes/IMPLEMENTATION_ASSUMPTIONS.md`에 기록하라. 단, 새로운 가정을 정식 게임 규칙으로 주장하지 말라.
8. 재질·메시·셰이더·모델 등을 프로젝트 내에서 생성하고, 외부 에셋이 필요하면 출처와 라이선스를 명시하라. 저작권/라이선스 불명 자료를 다운로드하지 않는다.
9. 코드 구조는 간결한 씬과 GDScript로 구성하라. P0가 성공하면 카메라/픽셀 렌더/조명 코드를 P1 전투 프로젝트에 재사용할 수 있도록 한다.
10. **가능한 실행 검증을 수행**하고, 에러·경고·실행 미검증 사항을 숨기지 말라. 실제 런타임 확인 없이 '화면이 정상적으로 보인다'고 단정하지 않는다.
11. 매 기능을 구현하기 전 승인이나 자잘한 선택지를 계속 묻지 않는다. 문서에 있는 임시 프리셋으로 우선 만들고, 시각 결과에 실질적인 영향을 주는 선택만 정리하라.

### 최우선 작업 순서

- (1) Godot 프로젝트 초기화 및 테스트 씬 작성
- (2) 고정 탑다운 카메라, WASD 이동, 단순하지만 읽히는 3D 자연환경·캠핑카·인물 생성
- (3) **원본 3D → 픽셀화 전환 및 내부 렌더 해상도 비교**
- (4) 밤 전환, 이동 광원, 캠핑카 헤드라이트 F 토글
- (5) 캠핑카 내부 씬 전환과 좁은 공간 가독성 테스트
- (6) 실행 확인·스크린샷/영상 캡처 또는 캡처 절차 제공, 시각적 문제 문서화

### 산출물

- 바로 Godot에서 열고 F6 또는 F5로 실행할 수 있는 프로젝트 디렉터리.
- 루트 `README.md`: 설치 요구 사항, 실행 방법, 조작, 렌더 토글, 알려진 문제.
- `notes/VISUAL_COMPARISON.md`: 픽셀 렌더 모드별 품질, 캐릭터 가독성, 픽셀 떨림, 그림자, 조명, 실내 판독성.
- `notes/IMPLEMENTATION_ASSUMPTIONS.md`: 확정되지 않은 기능을 임시로 처리한 목록.
- 테스트 캡처 파일 또는 명확한 캡처 단계(실제 파일이 없다면 있다고 주장하지 말 것).
- 마지막에는 P0 통과/보류 체크리스트를 작성하라.

### 완료 판단

**아래 질문에 시각적으로 답할 수 있어야 P0 완료다.**

- Godot 3D를 픽셀화한 게임 화면이 이 프로젝트의 아트 스타일로 쓸 만한가?
- 자연물/캐릭터/캠핑카의 비율이 탑다운 고정 화면에서 읽히는가?
- 캐릭터가 이동해도 화면이 불필요하게 떨리지 않는가?
- 밤에 등불과 캠핑카 라이트를 켜면 실제 플레이가 가능한가?
- 향후 실시간 전투를 올릴 수 있을 정도로 인물·적 위치가 명확한가?

결과가 마음에 들지 않는다면 퀘스트나 생활 콘텐츠를 먼저 만들지 말고 **픽셀화 방식, 모델 형태, 카메라 규모, 광원**부터 재설계하라.

## P0 다음 작업 (미리 맥락만 전달, 이번 단계에서는 구현하지 말 것)

사용자가 그래픽을 승인하면 **P1 코어 플레이 루프**를 만든다:

1. WASD 이동 및 마우스 방향 기본 공격(클릭당 1회).
2. 최소 몬스터 1종의 접촉 + TRPG 명중 판정, HP 피해, 피격/사망.
3. 몬스터 시체 직접 조사 후 전리품 획득.
4. 슬롯 없는 중량 기반 인벤토리(초과 시 속도 페널티, 상한 이후 추가 줍기 불가).
5. 캠핑카 직접 운전 및 실내 씬 진입, 실내 창고와 간이침대.
6. 휴식 시 수면 시간만큼 게임 시간 경과, 밤 라이트 확인.
7. 검은 고양이 임시 모델 및 사망 후 캠핑카 귀환의 최소 플로우.

**이 리스트는 P1 실행 범위를 제안하는 것이며 P0 작업 지시와 혼동하지 않는다.**
