# P0 그래픽 기술 검증 프로토타입 — 우선순위 1

> **목표:** 게임 전체를 만드는 것이 아니라 **Godot에서 '고정 탑다운 3D + 픽셀화 화면 + 현대 캠핑카 + 판타지 자연환경'이 실제로 만족스러운 모습으로 구현되는지** 가장 먼저 확인한다.  
> **상태:** P0 개발 명세 / 수치·아트 스타일·디버그 조작은 **검증용 임시 제안**. `GDD.md`의 확정 규칙을 변경하지 않는다.

## 0. 프로토타입의 핵심 질문

1. **3D 모델을 픽셀화했을 때** 인물, 나무, 길, 몬스터, 캠핑카가 서로 알아볼 수 있는가?
2. 카메라가 플레이어를 따라 움직일 때 **픽셀 떨림(shimmering), 텍스처 흔들림, 그림자 번쩍임**이 과하지 않은가?
3. 밤에 등불과 캠핑카 라이트를 켜면 **단순히 어두운 화면이 아니라 플레이 가능한 분위기**가 되는가?
4. 3D 지형과 자연물이 화면을 가려 **조작 캐릭터가 보이지 않는 문제**가 발생하지 않는가?
5. 화면 해상도와 픽셀 크기를 바꿔도 **게임 플레이를 해칠 정도로 작거나 뭉개지지 않는가**?
6. 현대식 캠핑카가 판타지 풍경에 놓였을 때, 시각적 대비가 **의도한 게임 콘셉트**로 읽히는가?

**P0에서 스토리·캐릭터 성장·던전·인벤토리 전체·요리·퀘스트를 만들지 않는다.** 그래픽이 어울리는지 확인이 우선이다.

## 1. 검증 씬 구성

### `visual_lab.tscn` — 야외

- **카메라:** 고정 탑다운 `Camera3D` (Orthogonal 우선 비교, 플레이어 추적, 회전 입력 없음).
- **지형:** 잔디 평원, 굽은 흙길, 작은 숲, 수변/연못, 돌과 작은 지형 높낮이.
- **환경 소품:** 스타일 일관된 나무 2~3형, 수풀 2형, 바위 2형, 작은 건축물 또는 울타리.
- **캐릭터:** 사람으로 읽히는 3D 인형/저폴리 임시 모델 1개. 걷기/서기/공격 1종을 최소 모션으로 표현. 최종 캐릭터 외형을 임의로 확정하지 말 것.
- **몬스터:** 슬라임 또는 단순한 판타지 생물 1종. 실제 전투 AI는 P1.
- **캠핑카:** **현대식 캠핑카로 알아볼 수 있는** 3D 임시 외형 1개. 바퀴·창문·문·헤드라이트 포함. 현대 RV라는 실루엣이 중요하며 박스 하나로 대체하지 않는다.
- **조명:** 낮 햇빛과 밤 약한 환경광, 차량 조명 1종, 캐릭터 휴대용 등불 1종.
- **화면 UI:** 현재 시각, 렌더 모드/해상도 표시, 디버그 키 힌트 정도만.
- **바닥 경로와 카메라**는 실제 이동 중 화면 끊김 테스트가 가능해야 한다.

### `camper_interior_lab.tscn` — 실내 (시각검증용 최소 구성)

- 캠핑카 외부와 **별도 씬**.
- 간이침대, 주방, 작업대, 수납 공간의 간단한 실루엣과 조명.
- 좁은 외형 대비 실내가 좀 더 넓게 느껴지는 공간 구조 실험. 마법 확장 전체 시스템은 아직 구현하지 않음.
- 실내 픽셀화가 야외와 일관적인지 확인. UI는 너무 작은 픽셀로 훼손하지 않는다.

## 2. 반드시 비교할 렌더링 방식

### 모드 1 — 저해상도 뷰포트 확대 (최우선 후보)

- 3D 월드를 낮은 해상도의 `SubViewport` 또는 프로젝트 저해상도 렌더 방식으로 그림.
- 결과를 선명한 픽셀 형태로 확대(가능한 한 nearest 필터/정수 배율 사용).
- **HUD는 별도의 고해상도 `CanvasLayer`에 그려서** 3D 장면 픽셀화에 영향을 받지 않게 한다.
- 확인할 것: 3D 오브젝트 가장자리, 소형 인물 가독성, 캐릭터 이동 시 픽셀 떨림, 그림자, 물과 반투명 오브젝트.

### 모드 2 — 3D 내부 해상도 스케일링 + nearest (비교 후보)

- Godot의 **3D 해상도 스케일 기능**으로 3D만 낮은 해상도에서 렌더링하고 2D UI는 선명하게 유지하는 방식을 확인.
- API·설정명은 **설치된 Godot 버전의 공식 문서**를 기준으로 구현.
- 모드 1과 결과를 같은 카메라 위치/같은 낮·밤 조건에서 비교.

### 모드 3 — 선택형 디더링/명암 단계화 (후처리 추가 실험)

- 모드 1 또는 2의 기본 결과를 만든 뒤, 밝은 면/그림자 영역의 단계형 명암, 팔레트 제한, 디더링을 **토글 가능한 별도 효과**로 추가.
- 과한 검은 테두리나 AI 일러스트풍 텍스처로 판독성이 저하되면 제외.
- "픽셀화"와 "카툰화"를 혼동하지 않는다. 먼저 **픽셀화가 정상 동작**하는지부터 테스트.

> 렌더러와 노드 조합에 따라 모드 1·2가 실제 내부에서 비슷한 접근으로 수렴할 수 있다. 그럴 때 **실제로 서로 다른 렌더 파이프라인을 억지로 만들지 말고**, 해상도/필터/쉐이딩을 독립적으로 비교할 수 있게 한다.

### 임시 비교 프리셋 (1280×720 디버그 창 기준)

| 프리셋 | 3D 내부 렌더 해상도 | 의도 |
|---|---|---|
| PXL-COARSE | 320×180 | 픽셀 큼, 4배 정수 확대 |
| PXL-SOFT | 640×360 | 픽셀 작음, 2배 정수 확대 |
| 3D-NATIVE | 1280×720 | 픽셀화 OFF 대조군 |

> 이 해상도들은 **기획 확정값이 아니라 실험 값**. 최종 타깃 모니터/화면비, 픽셀 밀도는 실제 영상을 본 뒤 선택한다. 가능하면 비교 화면에서 같은 카메라 화각·같은 모델 크기를 유지한다.

## 3. 아트 디렉션 — 프로토타입용 실무 지침

- **비교 목적은 고퀄리티 최종 아트 제작이 아님**. 일관된 재질·색상·조명만으로 기대하는 분위기를 검증하는 것.
- 캐릭터가 지나치게 작고 점처럼 뭉개지지 않아야 한다.
- 캠핑카는 멀리서도 일반 마차나 집이 아닌 **현대 캠핑카**로 보여야 한다.
- 자연물은 형태가 읽히는 면 중심으로 구성하고, 미세한 나뭇잎과 복잡한 털·풀 모델을 대량 배치하지 않는다.
- 지면과 수풀은 단순 반복 텍스처의 끊김과 명도 충돌을 체크한다.
- 오브젝트 색은 2~3단계의 명암 차이만으로도 구분 가능하게 우선 조정.
- 먼 화면의 장면뿐 아니라 **캐릭터가 나무 앞·뒤를 걸을 때** 캐릭터/그림자/가림 현상 확인.
- 휴대 광원은 밤에도 이동 방향과 가까운 위험물을 분간할 수 있게 해야 한다. 불필요하게 극단적으로 어둡게 만들지 않는다.
- 라이선스가 불명확한 외부 에셋을 무단 포함하지 않는다. 임시 메시/기본 재질 생성도 가능.

## 4. 테스트 장면 6종

| # | 장면 | 검증 목적 |
|---|---|---|
| 1 | 밝은 낮, 숲길을 따라 걷기 | 캐릭터·나무·길의 형태, 카메라 이동 중 픽셀 떨림 |
| 2 | 나무 뒤와 그림자가 겹치는 지점 이동 | 3D 가림/그림자 읽힘, 시야 확보 |
| 3 | 현대 캠핑카 앞에 캐릭터 서기 | 인물:차량 화면 비율, 현대 RV 실루엣 |
| 4 | 밤, 개인 등불 켜고 이동 | 주/야 차이, 개인 광원 가독성·퍼포먼스 |
| 5 | 밤, 캠핑카 F 라이트 ON/OFF | 실시간 광원, 그림자 번쩍임, 분위기 |
| 6 | 캠핑카 실내 전환 후 간이침대/주방 보기 | 외부·실내 씬 일관성, 픽셀 밀도, 작은 소품 판독성 |

가능하다면 밤 장면에서 슬라임 1종을 배치해 식별 가능성을 함께 점검한다.

## 5. 디버그 조작 (프로토타입 전용 임시)

- `WASD`: 캐릭터 이동.
- `F`: 캠핑카 근처에서 캠핑카 라이트 토글. **다른 조작과 충돌하지 않도록 P0에서는 광원만 담당**.
- `1` / `2` / `3`: PXL-COARSE / PXL-SOFT / 3D-NATIVE 비교.
- `N`: 낮 ↔ 밤 디버그 토글 (최종 게임 키로 확정하지 않음).
- `L`: 개인 등불 ON/OFF 디버그 토글 (최종 게임 조작 미정).
- `I`: 캠핑카 실내 테스트 씬 전환 (최종 게임 조작 미정).
- `H`: 도움말 및 현재 설정 표시.

실제 게임의 F키 충돌이나 인벤토리 키 바인딩은 P1에서 해결한다. 이곳의 임시 조작을 GDD 확정값으로 쓰지 않는다.

```text
project.godot
scenes/
  bootstrap.tscn

  actors/
    player_visual.tscn

  props/

  actors/
    prototype_player.gd
  vehicle/
    prototype_camper_lights.gd
shaders/
  optional_palette_dither.gdshader
resources/
  prototype_palette.tres  # 필요한 경우
notes/
  VISUAL_COMPARISON.md
  IMPLEMENTATION_ASSUMPTIONS.md

  (사용자가 생성·보관할 화면/영상 캡처)
```

상기 파일 이름은 **제안**이며 Claude Code가 실제 구현에 맞게 정리해도 된다. 중요한 것은 **시각 테스트와 정식 게임 데이터가 분리**되고, P0에서 검증한 렌더 모듈을 P1에 재사용할 수 있다는 점이다.

## 7. 통과/보류 판정

### 통과 조건

- [ ] Godot 프로젝트가 오류 없이 열리고 **직접 플레이**할 수 있음.
- [ ] 탑다운 고정 카메라로 걷고, 카메라 추적 중 픽셀 떨림을 관찰할 수 있음.
- [ ] 저해상도 2개 프리셋과 비픽셀화 대조군을 같은 위치에서 비교할 수 있음.
- [ ] 인물, 캠핑카, 나무, 적이 각각 알아볼 수 있는 실루엣을 보임.
- [ ] 주·야 전환과 차량 F 라이트를 확인할 수 있음.
- [ ] 캠핑카 실내 씬으로 전환하면 실내 장면을 볼 수 있음.
- [ ] 해상도, 카메라, 광원 변경 중 치명적 렌더 오류가 없고, 문제점이 문서화돼 있음.
- [ ] **주간 2장 + 야간 2장 + 실내 1장 + 픽셀 비교 1장** 이상 캡처 또는 캡처 가이드 제공.
- [ ] 가능하면 **10~20초 실제 게임 플레이 영상**으로 이동 시 픽셀 떨림을 확인.

### 보류 신호

- 정지 이미지에서는 괜찮지만 걷기 시작하면 지형 전체가 튀고 반짝임.
- 작은 인물과 몬스터의 공격 방향이 구분되지 않음.
- 낮은 해상도에서 캠핑카가 판독 불가한 상자로 보임.
- 밤에 빛이 번져 화면 전체가 뿌옇고 캐릭터가 보이지 않음.
- 나무 및 건물 지붕에 가려 캐릭터가 빈번하게 사라짐.

**보류라면 콘텐츠를 추가하지 말고** 픽셀 밀도, 카메라 스케일, 오브젝트 크기, 재질/조명을 먼저 수정할 것.

## 8. Claude Code 첫 실행 순서

1. 현재 PC의 **설치된 Godot 안정 버전**, 렌더러, GPU 환경 확인. 없으면 설치 안내와 프로젝트 최소 요구 사항을 정리.
2. 최소 3D 장면과 고정 탑다운 카메라 생성.
3. 사람이 사람처럼, 캠핑카가 캠핑카처럼 보이는 단순 모델·재질 배치.
4. **픽셀화 이전의 정상 3D 화면**을 먼저 확보.
5. 저해상도 픽셀 확대 모드와 토글 추가.
6. 주/야, 차량 라이트, 개인 조명 추가.
7. 작은 실내 씬과 전환 테스트 추가.
8. 오류·시각적 문제를 기록하고 비교 캡처.
9. 사용자에게 'P0 그래픽 결과 확인' 체크리스트를 제공하고 P1 여부를 판단.
