# 주인공 모델 — AI 생성 모델 적용

사용자가 새로 뽑아 준 모델(`cartoon_character_3d_model.glb`, Tripo로 생성, T자 자세)을 주인공으로 씁니다. 원본에는 뼈대가 없어서,
Blender에서 게임용으로 다듬고 뼈대를 넣은 뒤 기존 `PlayerRig`(걷기·공격·사용·달리기 동작, 장비 표시, 스프라이트 베이크)에 연결했습니다.
이전 Meshy 모델과 그 전의 원형들(v1 절차적 모델, v2·v3 Blender 원형)은 이 모델로 대체되었습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `art_src/player/source_model.glb` | 사용자가 준 원본 그대로 (정적 메시, T자 자세, 삼각형 9.7만 개, 2K PBR 텍스처 3장, 뼈대 없음) |
| `art_src/player/player.blend` | 손질 + 뼈대 + 웨이트까지 들어간 Blender 파일 |
| `art_src/player/renders/rig_test_*.png` | 웨이트 확인용 기본 자세 / 시험 포즈(칼팔 앞으로 75°, 걸음) 렌더 |
| `assets/characters/player/player.glb` | 게임이 읽는 모델 (삼각형 2만 8천 개, 면마다 단색 정점 색, 셔츠는 별도 메시, 뼈 16개, 텍스처 없음) |
| `tools/blender/player_model_prepare.py` | 원본 → 게임 모델 변환 스크립트 |
| `scripts/actors/player_rig.gd` | 뼈대를 코드로 움직이는 주인공 리그 |

원본 모델을 바꿨을 때 다시 만드는 명령 (프로젝트 폴더에서):

```bat
blender -b -P tools/blender/player_model_prepare.py -- art_src/player/source_model.glb art_src/player assets/characters/player/player.glb
:: Blender가 없으면: pip install bpy  후  python tools/blender/player_model_prepare.py (같은 인수 3개)
```

이 작업 환경에서는 PyPI의 `bpy` 5.2.2(Blender를 파이썬 모듈로 만든 공식 패키지)로 실행했습니다.
다른 모델로 바꿀 때는 스크립트 위쪽의 `JOINTS`(관절 위치), `ARMS_DOWN`(T자 → 팔 내린 각도), `HEAD_FROM`을 그 모델에 맞게 다시 재야 합니다.

## 변환 단계

1. **크기·위치**: 키를 1.74 m(이전 게임 모델과 같은 키)로 맞추고, 발바닥을 0에 두고 가운데로 옮김. 방향은 그대로(정면 = glTF +Z)
2. **정점 용접**: 원본은 UV 경계마다 정점이 갈라져 있어서, 그대로 뼈대를 붙이면 움직일 때 옷·얼굴이 찢어짐. 같은 자리 정점을 합침(UV는 면 모서리 단위라 유지됨)
3. **색 영역 읽기**: 원본 텍스처를 색 몇 가지(피부·수염·청바지·부츠·티셔츠·코·셔츠 빨강·짙은 빨강·검정)로 묶음. 셔츠 체크는 한 "셔츠" 영역으로 합치고(빨강이 섞인 덩어리 단위로 판별해서 눈 같은 검은 점은 남김), 작은 점은 지움. 고해상도 메시의 각 면이 어느 영역인지 기록
4. **삼각형 줄이기 + 다듬기**: 9.7만 → 2만 8천 개(스프라이트 베이커가 27동작 × 8방향 = 216벌을 한 번에 그리기 때문. 1만 6천 개로는 작은 눈이 깨져서 늘림). 수염 가닥·옷 주름 같은 잔 요철은 부피를 유지하며 매끈하게(라플라시안 스무딩)
5. **면마다 단색 칠하기**: 줄인 메시의 각 면에 가장 가까운 원본 면의 영역 색을 정점 색으로 칠함. 텍스처·UV는 버림. 얼굴 앞쪽(머리 높이)에 잘못 잡힌 짙은 빨강은 눈 색으로 바꾸고, 작은 눈 면은 정리 필터에서 보호
6. **셔츠 분리**: 셔츠 면을 별도 메시 "Shirt"로 떼어 냄(같은 뼈대·웨이트라 몸과 똑같이 움직임)
7. **뼈대**: hips · spine · chest · head · upper_arm/forearm/hand (좌우) · thigh/shin/foot (좌우). 관절 위치는 원본 메시를 높이별로 잘라서 잼
8. **웨이트**: Blender 자동 웨이트(열 확산 방식). 원본의 T자 자세에서 칠함(팔이 몸에서 떨어져 있어 깔끔함)
9. **팔 내리기**: 위팔을 수평에서 62° 내린 자세를 메시에 굳히고 그 자세를 새 기본 자세로 삼음. 배가 아주 커서(팔꿈치 높이 폭 ±0.46 m) 팔은 수직에서 28° 벌어져 배를 비켜 감. `PlayerRig`의 동작은 팔을 내린 자세에서 시작하기 때문

## 게임 쪽 연결 (`PlayerRig`)

- 기존 리그와 같은 함수(`pose`, `pose_action`, `pose_column`, `set_gear`, `set_lantern`, `lantern_anchor`)를 그대로 두어서, 플레이어·스프라이트 베이커 코드는 바꾸지 않았습니다.
- 예전 팔다리 노드 대신 같은 각도로 뼈를 돌립니다. 회전은 리그 축 기준이고, 아래팔은 위팔을 따라갑니다.
- **달리기(Shift)**: 동작 `run`(6칸)입니다. 팔꿈치를 굽힌 두 팔을 다리와 반대로 앞뒤로 흔들고, 보폭을 크게 하며 뒤로 빠진 다리의 무릎을 접습니다. 몸은 앞으로 기울이고 가슴은 엉덩이와 반대로 살짝 돌며 걸음마다 튑니다. 달리는 동안 칼은 날을 위로 세워 듭니다(팔 흔들림을 상쇄해 늘 거의 수직). (`PlayerRig.pose_run`) 처음의 "손 모은 아저씨 달리기"는 요청에 따라 평범한 달리기로 바꿨습니다. 스프라이트 시트는 27칸입니다. 미리보기: `captures/player/run_cycle_model.gif`(3D), `run_cycle_sprites.gif`(구운 스프라이트 5방향), 게임 확인은 `--tour=run`
- 걸음에는 뒤로 빠진 다리의 무릎 굽힘을 더했습니다. 대기 자세에서는 팔꿈치를 덜 굽혀 큰 주먹이 배 옆에 자연스럽게 내려오게 했습니다.
- 몸은 정점 색을 그대로 쓰는 툰 재질(`ProtoMesh` 2단 명암, 스페큘러 없음)입니다. 셔츠는 예전 모델처럼 큰 칸(약 23 cm)의 버펄로 체크를 박스 투영으로 입힙니다.
- 칼은 오른손 뼈, 방패는 왼쪽 아래팔 뼈, 물약·빵은 왼손 뼈, 등불은 엉덩이 뼈에 붙습니다(왼쪽 허리 옆, 배 아래 높이).
- 스프라이트 베이커는 각 사본을 트리에 넣기 전에 포즈를 잡는데, Skeleton3D는 트리 밖에서 바꾼 포즈를 스킨에 반영하지 않습니다. 그래서 `_ready()`에서 뿌리 뼈를 한 번 건드려 다시 계산하게 했습니다. 이게 없으면 시트의 모든 칸이 기본 자세로 구워집니다.

## 확인한 것 (xvfb 소프트웨어 렌더러)

- `--tour=sprites`: 8방향 × 27칸 시트에 대기·걷기 8칸·공격 5칸·마시기·먹기·시전·달리기 6칸이 모두 다른 자세로 구워짐. 낮·밤·근접·실내 캡처 정상
- 기존 투어 전체 회귀 확인 (결과는 커밋 메시지·보고에 기록)

## 알려진 한계

- 웨이트가 자동이라, 팔을 크게 드는 동작(공격)에서 셔츠 앞자락이 팔 쪽으로 조금 끌려갑니다. 게임 화면 크기에서는 거의 보이지 않습니다.
- 손가락·얼굴 표정 뼈는 없습니다(주먹 쥔 손 그대로).
- 색 영역 경계는 면 단위라 확대하면 계단처럼 보입니다(게임 크기에서는 1픽셀 이하).
- 셔츠 체크는 박스 투영이라, 팔을 크게 움직이면 무늬가 소매 위에서 조금 미끄러집니다.

## 자글자글함을 고친 이유 (기록)

처음 적용판은 원본 텍스처를 1024 px로 줄여 그대로 썼는데, 스프라이트가 점점이 깨졌습니다. 원인은 세 가지였습니다.
- 셔츠 체크·수염 결 같은 잔무늬가 26×36 픽셀로 줄면서 깨짐
- AI 생성 모델의 텍스처 아틀라스가 수백 개 조각인데, 삼각형을 줄이면 면이 조각 경계를 넘어가서 엉뚱한 색 점이 생김(청바지의 빨간 점 등)
- 잔 요철 때문에 명암이 얼룩짐

그래서 텍스처 대신 면마다 단색을 칠하고, 셔츠는 큰 체크로 바꾸고, 요철을 다듬었습니다.
